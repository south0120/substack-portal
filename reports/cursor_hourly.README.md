# `cursor_hourly.csv` の読み方

🔑 **何のための記録か**: `cursor`（取り込みが何誌目まで進んだか）を細かく残して、
**「1回も進まなかった」と「ちょうど1周した」を区別できるようにする**ため。
`daily_stats.csv` は1日1回なので、cursor が feeds 数（約2,700）で折り返すと両者が区別できない
（実例: 2026-08-29 と 08-30 の cursor がどちらも 1222 で、判定不能になった）。

## 🔴 読む前に知っておくこと

このファイルは `.gitattributes` で **`merge=union`** にしてある。
追記専用なので、push が衝突した時に「**両方の行を残す**」で自動解決させるため。
🔴 **union は行を増やす**。なので次が起こりうる:

| 起こること | 対処 |
|---|---|
| 同じ時刻に近い行が複数（別 run が同じ分に記録） | 秒まで記録してあるので区別できる |
| **ヘッダ行が2行以上**（生成が同時に走った） | **`http` が数字でない行は捨てる** |
| `http=500` の行に cursor が空 | **cursor の差分には使わない**（可用性のデータとしては使う） |

## ✅ 集計の手順（この順でやること）

```
1. http が数字でない行を捨てる      … ヘッダの重複を落とす
2. 時刻でソートする                … union は順序を保証しない
3. cursor の差分は http=200 の行だけ … 500 の行は cursor が空
4. 折り返しを補正する               … c1 < c0 なら +feeds数。
   🔴 ただし「1周ぶん進んで同じ値」は **記録が細かくないと区別できない**。
      このファイルを作った理由がそこなので、**間隔が空いた区間は判定しない**
```

## 🔴 `articles_cached` を「いまの記事数」として読まないこと

2026-09-08 の修正(`c3f3ccb`)以降、`/api/health` の `articles`/`writers` は **meta のキャッシュ**で、
**TTL 20時間 ＝ 実質1日1回**しか更新されない。so 毎時 記録しても**同じ値が並ぶ**。
`counts_at` 列が「その件数がいつ時点か」を持っているので、**必ず一緒に読むこと**。
🛑 正確な件数が欲しいからといって `COUNT(*)` を戻さないこと（**2026-09-05〜 の障害に戻る**）。
